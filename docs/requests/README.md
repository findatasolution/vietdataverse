# Nhật ký yêu cầu (Product Requests)

Mỗi yêu cầu của chủ sản phẩm được ghi lại ở đây, kèm thứ đã làm và thứ **cố ý
không** làm. Mục đích không phải là báo cáo thành tích: nó để trả lời được câu
"vì sao hệ thống lại thế này" sau sáu tháng, khi lý do đã rơi khỏi trí nhớ của
tất cả mọi người.

## Quy ước

- Một file mỗi tháng: `YYYY-MM.md`. Mới nhất ở trên cùng.
- Mỗi mục có: ngày, yêu cầu **nguyên văn hoặc rút gọn trung thực**, kết quả,
  commit, và **phần "đã từ chối / hoãn" kèm lý do**.
- Ghi cả những yêu cầu **không làm được** và vì sao. Đó thường là mục có giá trị
  nhất khi đọc lại.
- Không sửa mục cũ. Thay đổi quyết định thì thêm mục mới trỏ ngược lại.

"PR" ở đây là **Product Request** — yêu cầu sản phẩm, không phải pull request.
Repo này commit thẳng lên `main` (xem `CLAUDE.md` → Git Workflow Rules), nên
pull request không phải đơn vị ghi nhận tự nhiên.
